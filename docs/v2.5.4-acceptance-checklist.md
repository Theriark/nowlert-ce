# Notifinho v2.5.4 acceptance checklist

## Automated

- [ ] Python compilation passes.
- [ ] JavaScript syntax validation passes.
- [ ] YAML and production Compose validation pass.
- [ ] Documentation and packaged-icon validation pass.
- [ ] Focused v2.5.4 tests pass.
- [ ] Complete pytest suite passes.
- [ ] Release-candidate image builds.
- [ ] Image reports version 2.5.4 and schema 9.

## Discord

- [ ] Root packaged icon is uploaded and visible.
- [ ] Padded packaged icon is uploaded from `assets/icons/discord/` and visible.
- [ ] Execute Webhook contains `with_components=true` and `wait=true`.
- [ ] Returned Discord message contains the uploaded attachment.
- [ ] Returned Thumbnail media links to that attachment.
- [ ] Missing packaged icon fails safely instead of sending a broken URL.
- [ ] Real Xen Orchestra or Zabbix WebUI test displays the correct image.
- [ ] Real generic Notifinho WebUI test displays the Notifinho image.

## Destination health

- [ ] Failed test persists after browser refresh.
- [ ] Failed test persists after container restart.
- [ ] Destination card displays the safe failure reason and HTTP status.
- [ ] Routing Flow destination node turns red after a failed test.
- [ ] Routing Flow incoming arrow turns red after a failed test.
- [ ] Successful retest returns the destination card to passed.
- [ ] Successful retest returns Routing Flow to green.
- [ ] Enabled/configured but never-tested destinations remain neutral/active.

## Migration and production

- [ ] Pre-deployment config, state, and secrets backup exists.
- [ ] Automatic schema-8 database backup exists.
- [ ] Production reports version 2.5.4 and schema 9.
- [ ] Existing destinations, routes, users, tokens, settings, and history remain.
- [ ] Restart count remains zero.
- [ ] No startup traceback or database integrity error appears.
- [ ] v2.5.3 rollback backup path is recorded.
