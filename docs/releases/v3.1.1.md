# Nowlert CE v3.1.1 release notes

Nowlert CE v3.1.1 is the post-v3.1.0 QA, route-editor, administration, history,
and immutable-release hardening release.

It keeps database schema **9** and the **`platform_database_v1`** configuration
model. No database migration is required from v3.1.0.

## Highlights

### Administration

- Administrators can permanently delete eligible users after explicit
  confirmation.
- User deletion is protected by server-side account/ownership constraints and
  is audited.
- Administrators can permanently delete one selected private state backup
  without affecting other snapshots.
- Private backup deletion is separate from restore and is audited.
- The sidebar profile chip now uses the authoritative account role and displays
  **Admin** for administrators.

### Delivery History and Audit Log

- Delivery History no longer shows duplicate/redundant outcome badges or empty
  placeholder decoration.
- Delivery History and Audit Log use the same bottom pagination layout.
- **Top** is aligned with First/Previous/Next/Last on the left.
- **Entries** remains on the right side of that row.
- The current page is edited directly inside `Page [n] of N - X items`.
- Enter performs direct page navigation; the separate Go button is removed.
- Page-size persistence and existing scroll behavior are preserved.

### Route editing

- Redundant Excluded Severities and Excluded Statuses controls are removed from
  the route editor.
- Unselected severity/status values are implicitly excluded.
- Included Severities and Included Statuses use the normal selected-option
  highlight rather than an additional green/red color system.
- Individual options can be selected/deselected with a normal click without
  requiring Ctrl/Cmd.
- Native range/drag selection remains available.
- Route criteria are scoped to the selected integration/input contract.
- Full-list criteria are displayed correctly on the Routes page after save.

### Immutable release flow

- Cumulative work is integrated on `development`.
- CI on `development` builds/deploys the Development candidate.
- Stage reuses the exact immutable Development digest and advances `stage` to
  the promoted source commit.
- `main` is fast-forwarded to that same Stage-approved source before Production
  Reference.
- Production Reference requires `source == main == stage`, verifies the Stage
  image/ledger/evidence, and promotes the same digest without rebuild.
- Release finalization runs from `main` and creates the annotated version tag and
  GitHub Release on that exact source commit.
- Stable GHCR/Docker Hub version + `latest` aliases are registry copies of the
  approved digest; they are not rebuilt from the release tag.

## Compatibility

- Database schema: **9**
- Configuration model: **`platform_database_v1`**
- Persistent state path: **`/nowlert/state`**
- Python: **3.13**
- Existing v3.1.0 state can be used directly after a matched backup is taken.
- Existing `NOWLERT_*` environment variables and `/api/v2` management contract
  remain the supported runtime identity.

## Upgrade from v3.1.0

1. Record the currently running image/version.
2. Back up `config`, `state`, and external `secrets` as one matched set.
3. Pull/pin `theriark/nowlert-ce:3.1.1` (or the published immutable digest).
4. Redeploy without changing the documented `/nowlert` mounts.
5. Verify `/api/health` reports `3.1.1`.
6. Verify login and the administrator role chip.
7. Verify routes, destinations, Delivery History, Audit Log, Users, and Backups.
8. Perform a safe destination test or other environment-appropriate delivery
   validation.
9. Keep the matched pre-upgrade backup until acceptance is complete.

## Rollback

Because v3.1.1 does not introduce a schema migration, source/image rollback to
v3.1.0 is straightforward when no incompatible state change has been made.
For conservative recovery, stop Nowlert, restore the complete matched
pre-upgrade config/state/secret set, pin the previous image, and verify health
and routing before restoring normal traffic.
