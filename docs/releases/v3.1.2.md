# Nowlert CE v3.1.2 release notes

Nowlert CE v3.1.2 is a maintenance, documentation, dependency, and release-safety
update on the v3.1.x line.

It keeps database schema **9** and the **`platform_database_v1`** configuration
model. No database migration is required from v3.1.1.

## Highlights

### First-time product understanding

- The README opening now leads with **Infrastructure reports. Nowlert delivers.**
- The first screen states the Community Edition positioning, supported input and
  destination families, the Receive → Normalise → Route → Deliver flow, and the
  direct Quick Start path.
- Existing deployment commands and technical depth remain available below the
  first-screen summary.

### Maintenance

- Refresh production dependencies included in the v3.1.2 candidate, including
  `charset-normalizer` 3.5.1.
- Keep the existing schema-9 state and configuration model unchanged.

### Release safety

- Stage source advancement is fast-forward-only; the workflow no longer uses a
  forced branch update.
- Stage ref verification polls after the GitHub ref update so eventual
  consistency cannot produce the false-negative observed during the v3.1.2
  release rehearsal.
- Release finalization requires the requested version tag to exactly equal
  `v` + the `VERSION` embedded in the source candidate.
- Release finalization requires the matching v3.1.2 release notes and QA
  checklist to exist on the source commit before publication.
- The immutable-image invariant remains unchanged: one Development image digest
  is promoted through Stage and Production Reference and then copied to stable
  registry aliases without rebuild.

## Compatibility

- Database schema: **9**
- Configuration model: **`platform_database_v1`**
- Persistent state path: **`/nowlert/state`**
- Python: **3.13**
- Existing v3.1.1 state can be used directly after a matched backup is taken.
- Existing `NOWLERT_*` environment variables and `/api/v2` management contract
  remain the supported runtime identity.

## Upgrade from v3.1.1

1. Record the currently running image/version.
2. Back up `config`, `state`, and external `secrets` as one matched set.
3. Pull/pin `theriark/nowlert-ce:3.1.2` or the published immutable digest.
4. Redeploy without changing the documented `/nowlert` mounts.
5. Verify `/api/health` reports `3.1.2`.
6. Verify login, routes, destinations, Delivery History, Audit Log, Users, and
   Backups.
7. Keep the matched pre-upgrade backup until acceptance is complete.

## Release provenance

The final v3.1.2 release must be built once from the version-complete
`development` commit. The exact immutable digest is then promoted through Stage
and Production Reference. Final Development, Stage, and Production Reference
run IDs are supplied to the finalizer before the annotated `v3.1.2` tag and
GitHub Release are created.

Stable GHCR and Docker Hub `3.1.2` and `latest` aliases are registry copies of
that same approved digest; they are not rebuilt from the release tag.

## Rollback

Because v3.1.2 does not introduce a schema migration, source/image rollback to
v3.1.1 remains straightforward when no incompatible state change has been made.
For conservative recovery, stop Nowlert, restore the complete matched
pre-upgrade config/state/secret set, pin the previous image, and verify health
and routing before restoring normal traffic.

See the [v3.1.2 QA checklist](../v3.1.2-qa-checklist.md) and
[deployment/release guide](../deployment.md).
