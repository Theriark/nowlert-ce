# Nowlert CE v3.1.5 QA checklist

Use this checklist for the v3.1.5 Community Edition release candidate. Stage is
the final live runtime acceptance gate; release finalization must not rebuild or
redeploy the application.

## Source and release identity

- [ ] `src/version.py` reports `VERSION = "3.1.5"`.
- [ ] `.env.example` defaults to `theriark/nowlert-ce:3.1.5`.
- [ ] `compose.production.yaml` defaults to `theriark/nowlert-ce:3.1.5`.
- [ ] README and Docker Hub documentation identify v3.1.5 as current stable.
- [ ] `docs/releases/v3.1.5.md` exists on the candidate source commit.
- [ ] This checklist exists on the candidate source commit.
- [ ] The `v3.1.5` tag and GitHub Release do not exist before finalization.

## Repository and automation cleanup

- [ ] Active workflow definitions are exactly Continuous Integration,
      Development Image, Docker Release Aliases, Finalize CE Release, and
      Promote CE to Stage.
- [ ] Obsolete CE runtime-drift workflow files are absent.
- [ ] Dependabot repository configuration is absent.
- [ ] Maintained branches are `development`, `stage`, and `main`.
- [ ] Current release-policy documentation contains no active Production
      Reference gate.
- [ ] Historical release records remain unchanged.

## Compatibility and packaging

- [ ] Database schema remains **9**.
- [ ] Configuration model remains **`platform_database_v1`**.
- [ ] Existing v3.1.4 state opens without a migration.
- [ ] Existing `NOWLERT_*` deployment settings remain compatible.
- [ ] Approved v3.1.0 screenshots remain packaged and referenced because this
      release does not change the visual design.
- [ ] Current operator guides and integration indexes remain packaged.

## CI and Development candidate

- [ ] `development` CI is green before the Development Image build.
- [ ] Development Image builds the exact current `development` source commit.
- [ ] Development Image verifies version `3.1.5` and approved branding.
- [ ] Development deploys successfully and `/api/health` reports `3.1.5`.
- [ ] Record the exact immutable image digest.
- [ ] Record the successful Development Image workflow run ID.

## Stage final acceptance

- [ ] Stage promotion is dispatched from `development` with the exact immutable
      Development digest and source SHA.
- [ ] The full notification-silent gate runs in an isolated network namespace.
- [ ] All automated tests pass in the Stage gate.
- [ ] The exact immutable Development digest is deployed to Stage without
      rebuild.
- [ ] Stage `/api/health` returns two consecutive HTTP 200 `status=ok`
      responses with version `3.1.5`.
- [ ] Passive Stage promotion smoke passes with external notification delivery
      disabled.
- [ ] Stage desired-state evidence records the exact source SHA, image digest,
      application ID, health URL, and promotion run.
- [ ] `stage` advances to the candidate source using a fast-forward-only ref
      update.
- [ ] Record the successful Stage promotion workflow run ID.

## Main source gate

- [ ] Compare current `main` to the Stage-approved source.
- [ ] `main` can advance by fast-forward only (`behind_by == 0`).
- [ ] Advance `main` with `force=false`.
- [ ] Re-read `main` and `stage`; both equal the exact candidate source SHA.
- [ ] `main` CI completes successfully before release finalization starts.

## Release finalization

- [ ] Run `finalize-release.yml` from `main` with version `v3.1.5`.
- [ ] Finalizer verifies `source_commit == main == stage`.
- [ ] Finalizer verifies source version `3.1.5` matches requested tag `v3.1.5`.
- [ ] Finalizer verifies the successful Development and Stage workflow evidence.
- [ ] Finalizer verifies the live Stage application uses the exact approved
      immutable digest and expected version.
- [ ] Finalizer verifies Stage desired-state evidence matches the candidate.
- [ ] Release evidence is written.
- [ ] Annotated `v3.1.5` tag is created on the exact approved source commit.
- [ ] GitHub Release `v3.1.5` is created with release evidence attached.
- [ ] No application deployment or image rebuild occurs during finalization.

## Stable registry aliases

- [ ] Run `docker-release.yml` only after the `v3.1.5` tag exists.
- [ ] `ghcr.io/theriark/nowlert-ce:3.1.5` resolves to the approved digest.
- [ ] `ghcr.io/theriark/nowlert-ce:latest` resolves to the approved digest.
- [ ] `docker.io/theriark/nowlert-ce:3.1.5` resolves to the approved digest.
- [ ] `docker.io/theriark/nowlert-ce:latest` resolves to the approved digest.
- [ ] Registry aliases are copies of the approved image; no tag-based rebuild is
      performed.

## Rollback readiness

- [ ] Matched `config`, `state`, and external `secrets` backup is retained.
- [ ] Previous v3.1.4 immutable image/digest is recorded.
- [ ] Rollback verification covers health, login, routes, destinations,
      Delivery History, Audit Log, Users, and Backups.
