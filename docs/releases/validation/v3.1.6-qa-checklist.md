# Nowlert CE v3.1.6 QA checklist

Use this checklist for the v3.1.6 Community Edition release candidate. Stage is
the final live runtime acceptance gate; release finalization must not rebuild or
redeploy the application.

## Source and release identity

- [ ] `src/version.py` reports `VERSION = "3.1.6"`.
- [ ] `.env.example` defaults to `theriark/nowlert-ce:3.1.6`.
- [ ] `compose.production.yaml` defaults to `theriark/nowlert-ce:3.1.6`.
- [ ] README and Docker Hub documentation identify v3.1.6 as current stable.
- [ ] `docs/releases/v3.1.6.md` exists on the candidate source commit.
- [ ] This checklist exists on the candidate source commit.
- [ ] The `v3.1.6` tag and GitHub Release do not exist before finalization.

## Repository and automation model

- [ ] Active workflow definitions are exactly Continuous Integration,
      Finalize CE Release, and Promote CE to Stage.
- [ ] There is no standalone Development Image workflow.
- [ ] There is no standalone Docker Release Aliases workflow.
- [ ] Continuous Integration owns the Development build/deploy after a green
      `development` push.
- [ ] Continuous Integration does not run for ordinary pushes to `main`.
- [ ] Promote CE to Stage owns only the `stage` ref and never updates `main`.
- [ ] Finalize CE Release owns the only Stage -> `main` promotion and stable
      GHCR/Docker Hub alias publication.
- [ ] Current release-policy documentation contains no active Production
      Reference gate.
- [ ] Historical release records remain unchanged.

## Compatibility and packaging

- [ ] Database schema remains **9**.
- [ ] Configuration model remains **`platform_database_v1`**.
- [ ] Existing v3.1.5 state opens without a migration.
- [ ] Existing `NOWLERT_*` deployment settings remain compatible.
- [ ] Approved v3.1.0 screenshots remain packaged and referenced because this
      release does not change the visual design.
- [ ] Current operator guides and integration indexes remain packaged.

## CI and Development candidate

- [ ] The v3.1.6 release-prep PR CI is green before merge.
- [ ] After merge, `development` Continuous Integration is green.
- [ ] That same successful `development` CI run builds the exact current source
      commit and publishes `development` plus `sha-<source>` tags.
- [ ] CI verifies version `3.1.6` and approved branding inside the immutable
      Development image.
- [ ] CI deploys the exact immutable digest to CE Development.
- [ ] Development `/api/health` reports `3.1.6`.
- [ ] Record the exact immutable image digest.
- [ ] Record the successful `development` Continuous Integration run ID.

## Stage final acceptance

- [ ] Stage promotion is dispatched from `development` with the exact immutable
      Development digest and source SHA.
- [ ] The full notification-silent gate runs in an isolated network namespace.
- [ ] All automated tests pass in the Stage gate.
- [ ] The exact immutable Development digest is deployed to Stage without
      rebuild.
- [ ] Stage `/api/health` returns two consecutive HTTP 200 `status=ok`
      responses with version `3.1.6`.
- [ ] Passive Stage promotion smoke passes with external notification delivery
      disabled.
- [ ] Stage desired-state evidence records the exact source SHA, image digest,
      application ID, health URL, and promotion run.
- [ ] `stage` advances to the candidate source using a fast-forward-only ref
      update.
- [ ] `main` remains unchanged after Stage promotion.
- [ ] Record the successful Stage promotion workflow run ID.

## Release finalization

- [ ] Run `finalize-release.yml` from `stage` with version `v3.1.6`.
- [ ] Finalizer verifies `source_commit == stage`.
- [ ] Finalizer verifies current `main` can fast-forward to the Stage-approved
      source without force.
- [ ] Finalizer verifies source version `3.1.6` matches requested tag `v3.1.6`.
- [ ] Finalizer validates the successful `development` Continuous Integration
      run and the successful Stage promotion run.
- [ ] Finalizer verifies the live Stage application uses the exact approved
      immutable digest.
- [ ] Finalizer verifies Stage desired-state evidence matches the candidate.
- [ ] Finalizer advances `main` to the exact Stage-approved source with
      `force=false` and verifies ref propagation.
- [ ] No redundant Continuous Integration run starts from the `main` update.
- [ ] `ghcr.io/theriark/nowlert-ce:3.1.6` resolves to the approved digest.
- [ ] `ghcr.io/theriark/nowlert-ce:latest` resolves to the approved digest.
- [ ] `docker.io/theriark/nowlert-ce:3.1.6` resolves to the approved digest.
- [ ] `docker.io/theriark/nowlert-ce:latest` resolves to the approved digest.
- [ ] Registry aliases are copies of the approved image; no tag-based rebuild is
      performed.
- [ ] Release evidence is written.
- [ ] Annotated `v3.1.6` tag is created on the exact approved source commit.
- [ ] GitHub Release `v3.1.6` is created with release evidence attached.
- [ ] No application deployment or image rebuild occurs during finalization.

## Rollback readiness

- [ ] Matched `config`, `state`, and external `secrets` backup is retained.
- [ ] Previous v3.1.5 immutable image/digest is recorded.
- [ ] Rollback verification covers health, login, routes, destinations,
      Delivery History, Audit Log, Users, and Backups.
