# Nowlert v3.1.0 release notes

Nowlert v3.1.0 is the Community Edition WebUI and operational-quality release.
It introduces the approved Nowlert owl identity and Amber Accent interface while
retaining the schema-9 platform model and the existing Nowlert deployment
contract.

## Highlights

- New professional Dashboard with delivery analytics, Recent Activity, Top
  Sources, Top Destinations, System Health, and Routing Flow.
- Approved Nowlert owl branding across login, navigation, favicon/application
  icon, empty states, and generic Discord notifications.
- Amber Accent dark interface with consistent management-page descriptions,
  headers, cards, forms, dialogs, tables, focus states, spacing, and responsive
  presentation.
- Browser Back and Forward navigation between Nowlert sections.
- Card-grid Destinations presentation.
- Routes, Delivery History, and Audit Log pagination improvements.
- Safer Integration Settings editing: Cancel, Close, and Escape no longer save,
  and modified forms ask before discarding unsaved changes.
- Restart reliability corrections and removal of the misleading restart-policy
  warning.
- Version-aware Dokploy deployment gates that wait for the expected running
  application version before smoke testing.

## Compatibility

- Database schema remains **9**.
- Configuration model remains **`platform_database_v1`**.
- Existing `NOWLERT_*` environment variables, API contracts, backup formats,
  state layout, and `/nowlert` container paths are retained.
- No database migration is introduced by v3.1.0 from v3.0.0.
- Existing v2.5.5 schema-9 state can be upgraded only as a matched backup set;
  the v3 runtime uses the Nowlert database/path identity documented for v3.

## Upgrade

1. Back up `config`, `state`, external secrets, logs if retained, external backup
   metadata, and the current deployment definition as one matched set.
2. Keep the previous image available for rollback.
3. Update the image to the v3.1.0 release image while preserving the documented
   `/nowlert` mounts.
4. Start Nowlert and verify `/api/health` reports `3.1.0`.
5. Verify login, destinations, routes, integration settings, delivery history,
   audit history, backup configuration, and at least one real notification.
6. Keep the pre-upgrade matched backup until acceptance is complete.

## Rollback

Stop Nowlert, restore the complete matched pre-upgrade configuration/state/
secret set, restore the previous deployment definition, and start the previously
pinned image. Do not run an older image against a state database modified by a
newer incompatible schema.
